# 界面回归检查

## 两层检查

`e2e/layout.spec.ts` 使用真实浏览器滚动、点击与 DOM 位置断言，验证：

- 长页面只滚动主内容，顶栏/侧栏位置不变，文档不滚动。
- 矮屏侧栏导航区单独滚动，不改变主内容滚动位置，底部用户入口保持固定且可见。
- 导航图标与文字的中心线、20 px 图标框和 12 px 间距。
- 顶栏只保留主题图标，按钮高 32 px，和顶栏中心线误差不超过 1 px；每种视口都检查浅色、深色两种图标，报告记录实际位置。
- 上传区域为 88 px，第一条文件在首屏可见，页面无横向溢出。
- 切页回顶；手机抽屉可从长页面中打开、导航并关闭。
- 主题切换按钮有图标和可访问名称，刷新后保留选择。

`e2e/visual.spec.ts` 覆盖工作台、资源管理、文件管理，在桌面浅色、桌面深色、手机浅色下比较截图。`e2e/states.spec.ts` 覆盖桌面资源列表的空、失败、加载状态与登录页；手机抽屉也有截图。基准位于 `e2e/screenshots/`。

`e2e/components.spec.ts` 检查“组件与交互”的搜索、批量启停、文件选择与移除、重置、表单校验、失败后保留输入并重试、取消修改、删除确认与还原、数据状态恢复和消息反馈。三个项目分别为页面组合、表单页、编辑弹窗、状态页建立截图。

`e2e/resources.spec.ts` 检查声明过的服务端排序请求、后端字段错误显示与草稿保留、修正后重试、窄屏表单边界，以及批量部分失败的明细和选择状态。表单在桌面浅色、深色和手机上各有错误状态截图；位置测量等待有限的弹窗动画结束。资源写请求只在对应测试中显式拦截，不访问真实存储。

`e2e/account.spec.ts` 检查左下角用户入口的位置和图文居中、向上弹出、账户与设置导航、手机抽屉关闭、键盘 Enter 打开、Escape 返回焦点、点击外部关闭，以及通过 POST 退出后刷新仍显示登录页。账户菜单在三种视口主题下都有截图。测试夹具只声明必要的退出请求，其他未声明的写请求均使测试失败，防止演示操作意外调用业务接口。

当前范围是 Chromium 的视口截图，不代表完整跨浏览器、全设备或无障碍审计。视口以下内容由滚动行为测试补充检查，不能把截图通过等同于所有交互正确。

## 固定测试条件

- Playwright 精确版本 1.64.1，与镜像内浏览器一致。
- 本地与 CI 都使用相同 SHA256 固定的官方 Ubuntu Noble 镜像、Linux amd64；Mac 使用 Docker 运行，避免系统字体与浏览器渲染差异。
- 桌面 1280 × 800，手机 390 × 844；另有 1280 × 400 的矮窗口行为测试。
- zh-CN、Asia/Shanghai、设备像素比 1，固定日期与 API 数据，截图关闭动画并隐藏光标。
- 不使用宽泛的截图遮罩，不忽略动态业务区块，不使用大面积差异容忍；没有基准时默认失败。

测试启动独立的 Vite 前端服务（127.0.0.1:4174），渲染 `examples/dashboard` 的实际入口和页面。API 仅在 Playwright 中拦截，未知 API 请求和浏览器未捕获异常会使测试失败。它不启动 Workers、不读取 `.dev.vars`、不修改本地 D1/KV/R2，也没有生产代码中的测试路由或免登录开关。真实鉴权与存储行为仍由 workerd 测试验证。

独立测试不会验证已经打开的 5173 开发进程。修改 package.json 的 exports 或依赖后，应重启实际预览，必要时在 `examples/dashboard` 下运行 `npm run dev -- --force`，清除旧的包解析与预构建缓存。交付时还要打开实际预览页面，检查前端模块和真实 API；不能只用首页 HTML 的 200 状态判断可用。

## 日常运行

启动 Docker，然后在仓库根目录运行：

```sh
npm run check
npm run test:ui
```

首次运行需要下载镜像；脚本在临时容器内执行 `npm ci`，使用独立依赖卷，保留宿主机 node_modules。容器结束后移除临时卷。Docker 与 Playwright 只用于开发检查，不是应用运行时的依赖；消费项目可以运行自己的检查。

失败报告位于 `playwright-report/index.html`，包含预期、实际和差异图；`test-results/` 保存失败截图、trace，以及滚动位置附件。可在宿主机运行 `npx playwright show-report` 查看。

## 修改基准

先判断是意外回归还是期望的设计变更。修复回归不能靠更新基准解决。期望变更经过页面检查后，仅更新受影响测试，例如：

```sh
npm run test:ui:update -- --project=desktop-light --grep 'files keeps'
npm run test:ui
git diff -- e2e/screenshots
```

逐张查看 PNG 或报告中的差异，检查图文对齐、密度、明暗配色和首屏内容。把基准图片与对应代码放在同一提交中供审核；不能只因测试失败就批量接受所有截图。首次建基准也要人工查看，测试不能判断设计是否好看。

升级 Playwright 时同时更新 package.json、lockfile、Docker 脚本与 CI 中的镜像版本和 digest，使用新环境重新检查图片。不要直接拿 macOS 截图覆盖 Linux 基准。

## CI

`.github/workflows/check.yml` 有两个独立检查：现有 Workers/构建检查，以及固定容器中的 UI 行为与截图检查。UI 检查不更新基准、不自动部署；失败会阻止检查通过，并上传 7 天保留的 HTML 报告、差异图与 trace。仓库尚无远程地址，因此这里只配置并本地验证相同环境，未运行远程 GitHub Actions。

## 已验证的范围

32 张基准经过人工查看，包含组件示例、账户菜单和字段错误表单的桌面、深色与手机布局。本次契约接入只更新受排序表头影响的资源截图，新增三张字段错误表单基准；其他截图正常比较通过。

正常比对覆盖 65 项界面检查，另有 5 项按桌面/手机适用范围跳过；另运行 41 项 workerd 基础与接口检查、类型检查、构建和部署 dry-run。构建仍有既有的主包超过 500 kB 提示。

另外在独立临时副本中把上传高度从 88 px 改为 360 px，并取消外层视口约束。上传高度断言、内容滚动断言与文件页截图比较共 3 项都按预期失败；截图生成了明确的差异图。该验证没有修改正式预览的源码或数据，证明测试能拦截这两类已知回归。
