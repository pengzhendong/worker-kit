# 界面回归检查

## 两层检查

`e2e/layout.spec.ts` 使用真实浏览器滚动、点击与 DOM 位置断言，验证：

- 长页面只滚动主内容，顶栏/侧栏位置不变，文档不滚动。
- 矮屏侧栏导航区单独滚动，不改变主内容滚动位置，底部用户入口保持固定且可见。
- 导航图标与文字的中心线、20 px 图标框和 12 px 间距。
- 顶栏只保留主题图标，按钮高 32 px，和顶栏中心线误差不超过 1 px；每种视口都检查浅色、深色两种图标，报告记录实际位置。
- 上传区域为 88 px，第一条文件在首屏可见，页面无横向溢出。
- 切页回顶；手机抽屉可从长页面中打开、导航并关闭。
- 主题切换按钮有图标和可访问名称，刷新后保留选择。

`e2e/collapse.spec.ts` 检查桌面侧栏的 232 / 72 px 切换、图标居中与名称提示、折叠后的账户菜单与键盘操作、刷新保留偏好、存储被禁用时仍能切换，以及桌面与手机切换时的抽屉和内容滚动。浅色、深色分别保存折叠侧栏与账户菜单截图；原有桌面基准中的顶栏新增折叠按钮，需人工核对差异后更新。

`e2e/visual.spec.ts` 覆盖工作台、资源管理、文件管理，在桌面浅色、桌面深色、手机浅色下比较截图。`e2e/states.spec.ts` 覆盖桌面资源列表的空、失败、加载状态与登录页；手机抽屉也有截图。基准位于 `e2e/screenshots/`。

`e2e/components.spec.ts` 检查“组件与交互”的搜索、批量启停、文件选择与移除、重置、表单校验、失败后保留输入并重试、取消修改、删除确认与还原、数据状态恢复和消息反馈。三个项目分别为页面组合、表单页、编辑弹窗、状态页建立截图。

`e2e/media.spec.ts` 检查媒体不预载、真实音频波形、键盘定位、视频播放时间推进、互斥播放、离开媒体页签停止播放、大文件保留普通试听、不可用文件的重试入口，以及图片预览与 Escape 关闭。媒体示例在浅色、深色、手机各有静态首屏基准；播放过程使用行为断言，避免用随机播放帧比较截图。图片预览尊重系统减少动态效果设置。

2026-10-26 的开源组件接入另外验证：原生 Image.PreviewGroup 的键盘前后切换；ProTable 工具按钮的键盘打开、密度变化、列隐藏与会话客户端刷新；ModalForm 的异步提交防重、服务错误后保留草稿，以及只读权限下列设置不能恢复操作列。ProForm 会插入隐藏输入，表单边界断言只测量实际可见的控件。媒体示例增加第二张本地 SVG，资源页使用上游表格布局；人工查看明暗、手机、空/失败/加载、字段错误和折叠账户背景后，更新对应的 20 张基准，其余基准保持不变。

`e2e/resources.spec.ts` 检查声明过的服务端排序请求、后端字段错误显示与草稿保留、修正后重试、窄屏表单边界，以及批量部分失败的明细和选择状态。表单在桌面浅色、深色和手机上各有错误状态截图；位置测量等待有限的弹窗动画结束。资源写请求只在对应测试中显式拦截，不访问真实存储。

`e2e/account.spec.ts` 检查左下角用户入口的位置和图文居中、向上弹出、账户与设置及 API 中心导航、API 中心不出现在主导航、手机抽屉关闭、键盘 Enter 打开、Escape 返回焦点、点击外部关闭，以及通过 POST 退出后刷新仍显示登录页。账户菜单在三种视口主题下都有截图。测试夹具只声明必要的退出请求，其他未声明的写请求均使测试失败，防止演示操作意外调用业务接口。

`e2e/tools.spec.ts` 检查开发工具的本地、项目、模块、可选能力四个页签、原生工具地址和新标签属性、可复制命令、实际模块路径和授权标识、未配置状态，以及应用内导航回顶。运行与恢复页签在 lifecycle 测试中覆盖；五个页签均在三种视口主题下建立截图。原生面板需用实际开发服务器单独验收；`npm run check` 另检查生产前端不包含开发页面与本地调试链接。

`e2e/access.spec.ts` 检查只读账户的菜单与资源/文件/设置操作、直接 URL 越权和未知页面、权限服务失败重试，以及刷新后撤权时不再请求受保护数据。只读资源列表与禁止访问页面在三种视口主题下各有截图。权限仅在测试浏览器中模拟；实际接口拒绝和存储不变由 workerd 测试验证，预览没有角色模拟或免登录入口。

`e2e/lifecycle.spec.ts` 检查登录错误分流和重复提交、401 失效后草稿与权限重建、保留主题、切页取消查询、403/服务/网络错误保留身份、页面与应用根部渲染错误、局部错误重试、真实下载链路及保留策略关闭状态。渲染错误由测试网络拦截替换组件模块触发，不添加生产测试路由。运行页与页面错误状态各有三张截图。

`e2e/runtime.spec.ts` 检查正式运行状态页的图标、版本与真实检查记录、未接入指标、依赖和平台失败、单位与零流量语义、权限先于请求，以及自动检查只刷新依赖并在离页后停止。浅色、深色与手机各有基准。新增导航和 API 操作引起的旧基准变化需人工确认；与功能无关的细微渲染差异保留原基准。

当前范围是 Chromium 的视口截图，不代表完整跨浏览器、全设备或无障碍审计。视口以下内容由滚动行为测试补充检查，不能把截图通过等同于所有交互正确。

`e2e/api-center.spec.ts` 检查同源 Scalar 实际请求、选定操作文档、父页面 hash 隔离、无外部请求、文档过期返回登录、Token 表单校验、一次展示、无浏览器持久存储、撤销确认，以及文档只读授权。交互均使用显式夹具，不在预览签发真实令牌。四类 API 页面状态在三种视口主题下各有截图。

## 固定测试条件

- Playwright 精确版本 1.64.1，与镜像内浏览器一致。
- 本地与 CI 都使用相同 SHA256 固定的官方 Ubuntu Noble 镜像、Linux amd64；Mac 使用 Docker 运行，避免系统字体与浏览器渲染差异。
- 桌面 1280 × 800，手机 390 × 844；另有 1280 × 400 的矮窗口行为测试。
- zh-CN、Asia/Shanghai、设备像素比 1，固定日期与 API 数据，截图关闭动画并隐藏光标。
- 不使用宽泛的截图遮罩，不忽略动态业务区块，不使用大面积差异容忍；没有基准时默认失败。

测试启动独立的 Vite 前端服务（127.0.0.1:4174），渲染 `examples/dashboard` 的实际入口和页面。API 仅在 Playwright 中拦截，未知 API 请求和浏览器未捕获异常会使测试失败。它不启动 Workers、不读取 `.dev.vars`、不修改本地 D1/KV/R2，也没有生产代码中的测试路由或免登录开关。真实鉴权与存储行为仍由 workerd 测试验证。

独立测试不会验证已经打开的 5173 开发进程。修改 package.json 的 exports 或依赖后，应重启实际预览，必要时在 `examples/dashboard` 下运行 `npm run dev -- --force`，清除旧的包解析与预构建缓存。交付时还要打开实际预览页面，检查前端模块和真实 API；不能只用首页 HTML 的 200 状态判断可用。

## 日常运行

启动 Docker，然后在仓库根目录运行：

```sh
npm run check
npm run test:ui
```

首次运行需要下载镜像；脚本在临时容器内执行 `npm ci`，使用独立依赖卷，保留宿主机 node_modules。容器结束后移除临时卷。Docker 与 Playwright 只用于开发检查，不是应用运行时的依赖；消费项目可以运行自己的检查。

失败报告位于 `playwright-report/index.html`，包含预期、实际和差异图；`test-results/` 保存失败截图、trace，以及滚动位置附件。可在宿主机运行 `npx playwright show-report` 查看。

## 修改基准

先判断是意外回归还是期望的设计变更。修复回归不能靠更新基准解决。期望变更经过页面检查后，仅更新受影响测试，例如：

```sh
npm run test:ui:update -- --project=desktop-light --grep 'files keeps'
npm run test:ui
git diff -- e2e/screenshots
```

逐张查看 PNG 或报告中的差异，检查图文对齐、密度、明暗配色和首屏内容。把基准图片与对应代码放在同一提交中供审核；不能只因测试失败就批量接受所有截图。首次建基准也要人工查看，测试不能判断设计是否好看。

升级 Playwright 时同时更新 package.json、lockfile、Docker 脚本与 CI 中的镜像版本和 digest，使用新环境重新检查图片。不要直接拿 macOS 截图覆盖 Linux 基准。

## CI

`.github/workflows/check.yml` 有两个独立检查：现有 Workers/构建检查，以及固定容器中的 UI 行为与截图检查。UI 检查不更新基准、不自动部署；失败会阻止检查通过，并上传 7 天保留的 HTML 报告、差异图与 trace。仓库尚无远程地址，因此这里只配置并本地验证相同环境，未运行远程 GitHub Actions。

## 已验证的范围

68 张基准经过人工查看，包含组件示例、账户菜单、字段错误表单、开发工具五个页签、只读列表、禁止访问、页面错误状态，以及 API 列表、Scalar 文档、Token 元数据与创建表单的桌面、深色与手机布局。API 中心入口现位于用户菜单；本次截图变更为侧栏移除入口、账户弹窗增加入口及手机抽屉同步调整。已检查差异与完整图片；内容区仅有最多 1/255 色值的边缘渲染差异，未改变布局。整张图片只有这种微小渲染差异时保留原基准。

完整范围为 146 项界面检查，另有 5 项按桌面/手机适用范围跳过；另有 78 项 workerd 基础与接口检查、5 项 Node 工具测试，以及类型检查、只读预检、构建、生产页面排除检查和部署 dry-run。菜单调整时全量交互检查通过；人工审核后对受影响页面另做正常截图比较。共用 Schema 后，API 中心与资源相关的 27 项界面检查再次正常比较通过，无需更新基准。构建仍有主包及独立 Scalar 文档包体积提示，文档只在独立页面加载。

另外在独立临时副本中把上传高度从 88 px 改为 360 px，并取消外层视口约束。上传高度断言、内容滚动断言与文件页截图比较共 3 项都按预期失败；截图生成了明确的差异图。该验证没有修改正式预览的源码或数据，证明测试能拦截这两类已知回归。

参考：[Playwright 视觉比较](https://playwright.dev/docs/test-snapshots)、[官方 Docker 环境](https://playwright.dev/docs/docker)。

## Actions 额度控制

自动检查只响应主分支提交和 PR，文档变动不启动；同一分支/PR 的新提交会取消过时任务。基础检查先执行并根据实际 Git diff 决定是否启动视觉 job：共享前端、模块/契约、演示、依赖、截图或检查配置改变时保留全量视觉检查，纯共享后端变动可跳过。缺少历史、首次提交和手动检查默认全量执行。基础检查失败时不启动视觉 job。

截图参数和基准不变；浏览器报告只在失败时上传，保留 3 天。视觉 job 使用 npm 下载缓存，超时 15 分钟；本地 `npm run test:ui` 仍是全量检查。此配置减少无关任务，不缩减需要运行时的 149 项界面检查。

## 观影交互回归

`e2e/video-player.spec.ts` 验证 Video.js 公开控件组合的倍速菜单、与音频互斥、原生全屏中的业务覆盖层、同 video 切源保留全屏/音量/倍速、固定显隐、键盘定位、网页全屏、长按取消和卸载清理。手机用 CDP 真实触摸事件检查纵向页面滚动、全屏长按与横向滑动共存。播放器在浅色、深色与手机下各有一张元素截图。示例增加折叠观影区后，资源列表页面截图因可滚动高度改变而向上移动 64px；三种主题/视口均已人工检查。

## 可视化资源网格

`MediaList layout="grid"` 为需要大缩略图的资源浏览提供可选布局。`e2e/media.spec.ts` 检查三类媒体的 144 px 卡片、112 px 高预览、控制条与下载不重叠、实际音视频播放，以及桌面浅色、深色、手机三个初始静态基准。截图前滚动到资源区域，播放验证在截图后执行，避免缓冲进度和播放帧进入基准。

`e2e/auto-page-size.spec.ts` 同时覆盖原来的单列列表与多列网格；验证高度变化、列数变化、极矮窗口至少保留一行、滚动不影响容量与最大数量限制。剪映实际 8891 预览另外检查 1440×900、1100×700、1920×1080、390×844、320×640 五种窗口、折叠侧栏、图片组预览与内容滚动。1440×900 时为 3 列 / 12 项，手机为 1 列；实际容量同时取决于工具栏高度与可用宽度。
