# 功能与验证边界

## 已接真实存储的功能

| 路线 | 实际能力 |
| --- | --- |
| Payload / SonicJS + 八套界面 | 原生登录、任务计划创建/执行/暂停/恢复、运行记录与依赖检查 |
| CMS 原生管理页 | 所选 CMS 的用户、内容、媒体和权限 |
| 轻量 Worker | KV 会话登录/注销、运行检查、非敏感配置、访问密钥签发/撤销、最近审计与 API 文档 |
| NuxtHub 全栈 | 通过实际 SDK 读写 D1 记录、KV 标签和 R2 文本文件；Nitro 缓存样例结果 |

各项界面中的操作会修改当前路线的真实示例数据。新业务的字段、校验和权限应由应用自己声明。

## 组件体验仍是示例

七套应用界面的表格、表单、弹窗、媒体预览、布局与主题页面用于比较原生组件。搜索、模拟任务、浏览器保存和本地文件选择使用 fixture，不代表任务已执行或文件已上传。

任务的真实业务入口是“业务工作台”；CMS 内容与媒体使用原生管理页。不要用组件体验页里的统计数字衡量业务运行状态。

## 验证范围

源码、依赖和模板版本固定后，分别检查构建、类型、workerd 认证与权限、存储写读、浏览器路由及移动布局，再组合成一个 Worker 部署。

本地 workerd、部署 dry-run 和包体积检查不能证明免费套餐的线上 CPU 配额一定满足要求。展示站不把尚未采集的平台指标写成零，也不把缓存后的切换耗时称为首次加载耗时。新业务上线后应依据 Cloudflare Observability 的真实请求与资源指标评估。
